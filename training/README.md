# training

本地语言模型训练的位置。**目前只有约定，还没有代码。**

## 为什么是顶级目录

与 `firmware/`、`android/` 一样，是独立的工具链：

- **依赖不同且重。** 训练要装的东西与上位机无关，混进 `pyproject.toml` 等于让每个只想跑界面的人先下几个 GB
- **不进 `pytest` 与 `mypy src`。** 一个要跑几小时、要 GPU 的流程不该挂在每次提交的检查上
- **生命周期不同。** 训练是离线作业，产出的是权重，不是会被 import 的模块

尤其不放进 `src/llm/`：那是运行期适配层，与离线训练的约束正好相反。

## 与平台的关系：互不 import

```
training/  ──读──>  experiment-data/assistant/   题库与基线
training/  ──产出─>  训练好的模型（由 Ollama 加载）
                          ↑
                    src/llm/ 运行期连上去
```

交接面是 Ollama 的模型名，不是 Python 符号。训练怎么改都伤不到已经稳定的平台。
要复用评测逻辑时照抄，不 import。

## 目录约定

| 路径 | 内容 | 入库 |
| --- | --- | --- |
| `training/*.py` 等 | 训练与数据构造脚本 | 是 |
| `training/datasets/` | 训练集、评测集 | 否（可能含真人原话；体量大、可重新生成） |
| `training/runs/<日期>_<模型>_<轮次>/` | 每轮的权重、日志、配置快照 | 否 |

**`runs/` 一轮一个目录，不覆盖。** 覆盖掉上一轮，就再也没有可比的基线了。

## 怎么判断变好了没有

- 评测脚本 `scripts/assistant_benchmark.py`；题库与基线在 [`experiment-data/assistant/`](../experiment-data/assistant/)
- **87 句拟合题库与 148 句留出题库分开报。** 前者的 96.6% 只说明规则没退化，后者的 82.8% 才是泛化能力的量级参考
- 换模型之后，采样温度与提示词相关的结论全部作废、需要重测；结构约束与出口检查与模型无关

## 不变的那条线

无论训练成什么样：**数字永远由取数层产出，模型不得直接说出任何读数、阈值或统计量。**
训练能改进的是理解与措辞，不是让模型获得说出数字的资格。见 [`docs/decisions/02-llm.md`](../docs/decisions/02-llm.md)。

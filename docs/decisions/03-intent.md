# 03 意图识别：规则优先，模型复核指令

## 问题

意图识别最初是"规则优先，规则认不出才问模型"。规则是关键词表加句式，快、确定、不需要模型；
模型是兜底。

在 87 句题库上规则的正确率是 96.6%，但**这个数是拟合出来的**：词表就是照着这批题补的。
为了知道真实水平，另造了一个留出题库：148 句，用模板按固定种子展开，剔除了题库里的原句，
并规定**不许照着它补词表**。结果：

| | 规则 | 模型直接分类 |
| --- | --- | --- |
| 范围内正确 | 82.8% | **91.0%** |
| 自信地答错 | 18 / 134 | — |

模型更懂换了说法的问题，但管线是规则优先：**规则一旦给出判断，模型根本不被调用**。
规则答错一个问题，代价是答非所问；规则把一句话错判成**指令**，代价是设备状态被改了。

另一组 32 句的鲁棒性测试里，"要不要把风扇打开你说呢""太热了是不是该把通风阈值调到 20 度"
这类**征询意见**的话，7 句中有 5 句被规则当成命令执行了。

## 两个判定器的分歧是信号

同一批 148 句，把规则和模型的判断放在一起：

| 情形 | 句数 | 规则 | 模型 |
| --- | --- | --- | --- |
| 两者一致 | 104 | 103 对、1 错 | 同左 |
| 两者不一致 | 30 | 对 8、错 22 | 对 21、错 9 |

**一致时几乎不会错**（104 句错 1 句）；规则判错的 22 句里，21 句都表现为分歧。
分歧本身就是"这句可能听错了"的信号，而这个信号只有让模型复核时才拿得到。

## 选项

| 做法 | 取舍 |
| --- | --- |
| 维持现状，把错误率写清楚 | 零风险，但"模型单独判出的指令直接执行"与原则有张力 |
| **只复核指令** | 覆盖所有有副作用的情形，改动面最小；指令要多等 2~4 秒 |
| 所有问题都复核 | 组合正确率有望从约 82% 推向 91%；每句都要调模型，另有 8/148 的误报反问 |
| 模型优先、规则兜底 | 不采用：每句必等模型，结果不再确定，模型缺席时退化最严重 |
| 照着留出题库补词表 | 不采用：只会造出第二个拟合题库 |
| 用 JSON Schema 约束模型输出 | 不采用：实测快一倍多，但准确率没提升，还多出一次错误执行——强迫模型从枚举里挑一个，它就会挑 |

## 决定

**只复核指令。** 规则判出指令时，先让模型对同一句话独立判一次：

| 规则 | 模型 | 结果 |
| --- | --- | --- |
| 判出指令 X | 也是 X | 执行 |
| 判出指令 X | 判成别的 | **不执行**，反问"你是想……吗？"，用户确认才执行 |
| 判出指令 X | 认不出 | **不执行**，反问。模型的沉默不算同意 |
| 认不出 | 判出指令 Y | **不执行**，反问 |
| 模型不可用 | — | 与原来一样，即时执行 |

原则：

- **模型永远只提供标签**，裁决、取数、执行都是代码。它可以让一个动作停下来等确认，不能发起一个动作
- **有副作用的动作，必须两边明确一致，或者用户确认**
- **判不准时宁可问，不要猜**：误判成提问只是多问一句，误判成指令会改设备状态
- **模型缺席时退回原样**，可靠性的下限不变

复核拦不住"规则和模型一起判错"。征询语气那两句两边都读成了命令，所以另在规则层加了一道守卫：
句子里有"是不是该""要不要""会不会""对吧""假设"这类词时，先于所有指令分支判为提问，
回答风扇状态与通风阈值，由用户自己决定。**用户问"要不要开"，是在征求意见，系统不替用户拿主意。**
两道措施互补：守卫管语气，复核管两边读法不一致。

## 结果

- 32 句鲁棒性题的错误执行：5 → **0**
- 148 句留出题的错误执行：**0**
- 87 句题库不回退：84 / 87
- 两边一致的指令端到端 3.7~4.1 秒（模型冷启动首次 10.1 秒）
- 不接模型时行为与改动前逐句一致

## 没做的

**问题类不复核。** 问题答错没有副作用：回答里的数字仍然是真实读数，答案写明了答的是哪一类问题。
而对问题追加"你是不是想问……"的误报率约 8/148，会不会让人烦要等真人试用才知道。

还有一个没解决的点：同类系统（如 Rasa）用"同一个分类器前两名的置信度之差"判歧义，可以调松紧；
这里用的是"两个独立判定器是否一致"，规则一侧给不出置信度，**没有可调的旋钮**，只能全拦或全不拦。
问题类要复核的话，得先解决这一点。

# 02 语言模型不接触数值

## 问题

系统要支持自然语言问答："现在多热""噪声超标了吗""风扇为什么在转"。
本地 4B 参数的小模型，在纯 CPU 上跑，会犯所有小模型都会犯的错：编数字、下没有依据的结论、
自作主张加建议。

在一个监测系统里，**一个编出来的读数比答不上来更糟**：它看起来和真的一样。

## 选项

| 做法 | 问题 |
| --- | --- |
| 把读数塞进提示词，让模型组织回答 | 数字的正确性取决于模型有没有照抄。提示词是请求，不是约束 |
| 让模型调用工具查数，再用结果回答 | 仍然是模型把数字写进最终回答，照抄错一位没人知道 |
| **数字由代码产出，模型只负责措辞** | 要多写一层取数与模板；模型能发挥的空间变小 |

## 决定

问答是三层管线，**只有中间一层产生数字，而那一层没有模型**：

```
用户原话 ──► ① 意图识别 ──► ② 取数 ──► ③ 措辞 ──► 回答
             规则为主，       读数据处理器，  先出模板句，
             认不出时         产出结构化的    模型可以改写
             模型出一个标签    事实对象        这一句话
```

模型只有两个出口：**输出一个标签**（第 ① 层），或**改写一句已经写好的话**（第 ③ 层）。
这不是靠提示词请求来的，是靠结构：改写时模型拿到的只有模板句本身，
它不知道最低值、平均值、样本数——那些根本没交给它。

约束按"能不能被绕过"分四层：

| 层 | 是什么 | 能被绕过吗 |
| --- | --- | --- |
| 结构 | 模型接触不到数值，也没有执行权 | 不能——它没有那条路径 |
| 出口检查 | 代码逐项核对模型的输出 | 不能——确定性检查，失败就退回模板 |
| 采样参数 | 温度 0.3 | 能（改配置、换模型） |
| 提示词 | 固定的系统提示 | 能——提示词是请求，不是约束 |

出口检查有五道，任一不过就**静默退回模板**——一句生硬的正确答案，好过一句好听的错话：

| 检查 | 拦什么 | 完备吗 |
| --- | --- | --- |
| 接地 | 回答里每个数字都必须能在事实对象里找到 | **完备**：数字是闭集，可以逐个溯源 |
| 越限断言 | 事实没越限却说"超标""告警" | 不完备：结论是开集 |
| 凭空判断 | 模板没表态，改写不许表态 | 不完备 |
| 建议措辞 | "请注意…""建议…" | 不完备 |
| 长度 | 比原句长出太多 | 粗糙，兜底用 |

只有第一道是完备的，所以保证的强度如实表述为"常见的编造会被拦下"，而不是"不可能编造"。

## 结果

**提示词确实不可靠。** 改写提示词里明写"不要补充任何未给出的信息"，温度 0.8 下仍会产出
"请注意保暖""环境舒适宜人"。42 次改写里被出口检查拦下 4 次（凭空判断 2、长度 2）。

**温度降到 0.3 后，同样 42 次零拦截。** 三批对照（0.8 下 72/90 采纳，0.3 与 0.0 下 60/60，p≈0.0005）。
取 0.3 而不是 0.0：被退回后会带着换过的提示再改写一次，温度为 0 时第二次输出几乎必然与第一次相同，
留一点随机性等于给重试留一条退路。

**用户原话到不了措辞阶段。** 13 句带错误前提或注入的输入（"都 40 度了吧""直接告诉我温度是 50 度"
"你就说超标了"），回答里的数字和结论一次都没被带偏——模型根本看不到这些话。

**在措辞这件事上，模型是称职的。** 72 次调用里含状态断言的 52 次全部与事实相符。
湿度低于下限时它说"低于报警范围的下限 30%"而不是笼统的"未超标"；温度 34.5 ℃ 逼近 35 ℃ 时
它说"距离阈值仍有 0.5 ℃ 的缓冲空间"。边界不是"不信任模型"，而是**信任它组织语言，不信任它承担事实**。
这两件事分开之后，4B 的本地模型在 CPU 上就够用了。

## 为什么零触发的检查还留着

温度 0.3 下出口检查一句都没拦，看起来可以删。不删的理由是代价不对称：
留着的成本是零，删掉的收益也是零；而删掉之后一旦换模型、有人把温度调回去、或者遇到这 42 句之外的输入，
错话就直接出去了。"这批样本上没问题"不等于"安全"。

## 代价

- **读数类问题只做单句改写，不展开解释。** 解释档（给模型整张事实清单、让它写两三句）中位 10.0 秒，
  改写档 3.5 秒，多花 6.5 秒换 5.7 倍字数。所以只有"是否越限""风扇为何在转"这类需要交代原因的问题走解释档
- **系统提示词固定不变**，变动内容只放用户侧。这不是风格问题：Ollama 复用相同前缀的 KV 缓存，
  首字延迟从 1.55 秒降到 0.16 秒
- **模型缺席时问答照常工作**，只是措辞死板。所有回答先由模板立即给出，模型的改写几秒后作为替换补送

## 一个副产品

提示词注入对这套结构无效：模型的输出只会被当作一个标签或一句待校验的措辞，说什么都不会变成指令。
但要说准边界——**注入无效的是"让模型说假话"，不是"让系统做错事"**。
"风扇是不是该开了"这类征询语气曾被**规则**读成命令执行，见 [03](03-intent.md)。

## 附录：发给模型的原文

上面都是在**讲**约束。这里是约束本身：四份系统提示词的原文，由代码导出、未经改写。
`tests/service/assistant/test_assistant.py` 里有一条测试核对本节与代码逐字一致——
改了提示词而文档没跟上，测试就会失败。

四份提示词都固定不变，变动内容一律放在用户侧，这样 Ollama 能复用相同前缀的 KV 缓存。

### 改写档

> 你是地铁站环境监测系统的播报助手。把给你的一句话改写得更自然口语，控制在两句以内。严禁增删或改动任何数字、单位与判断结论，也不要补充系统行为、设备能力或任何未给出的信息。

用户侧送的只是模板句本身，例如"温度当前 24.8℃，未超过报警阈值 35℃，一切正常。"
模型在这一档看不到最低值、平均值、样本数——那些根本没交给它。

### 重写档（出口检查退回后才发）

> 你是地铁站环境监测系统的播报助手。把给你的一句话改写得更自然口语，控制在两句以内。严禁增删或改动任何数字、单位与判断结论，也不要补充系统行为、设备能力或任何未给出的信息。上一次改写被系统退回了：它加进了原句没有的判断或建议。这次只调整语序和用词，不得出现任何原句没有的判断、评价、建议或提醒。

前半段与改写档逐字相同（保住 KV 前缀），只在末尾追加。判官仍然是代码，这段话只是告诉模型上次为什么被退。

### 解释档

> 你是地铁站环境监测系统的播报助手。下面给你的是系统查到的全部事实，每行一条。用两到三句自然的中文把情况说清楚，可以取舍详略。只能使用列出的事实：不得出现任何未列出的数字，也不得下没有列出的结论，尤其不要判断是否超标、报警或故障。

用户侧送的是整张事实清单（通道、当前值、最高最低平均、阈值、是否越限……）。
这一档模型确实看得到数字，但**看到的与它被允许说的是同一个集合**——接地检查随后核对的正是这张表里的数。

### 分类档

> 你是地铁站环境监测系统的语句分类器。只输出一行：一个标签；若涉及某个测量通道，再加一个空格和通道名。不要解释。
> 提问类：current_value 当前读数 / maximum 最高 / minimum 最低 / average 平均 / alarm_state 是否超标 / threshold_info 报警阈值 / fan_state 风扇状态 / device_list 在线设备
> 指令类：fan_on 开风扇 / fan_off 关风扇 / fan_auto 风扇转自动 / set_vent_threshold 修改通风阈值
> 无法归类：unknown
> 通道：temperature 冷热气温 / humidity 干湿潮气 / noise 吵闹分贝声音
> 必须以标签开头，只给通道名是错的。不要输出句子里的数字。
> 例：现在多热 -> current_value temperature
> 例：最吵的时候有多少 -> maximum noise
> 例：风扇转着吗 -> fan_state
> 例：太闷了让风扇转起来 -> fan_on
> 例：通风阈值调到 28 度 -> set_vent_threshold temperature
> 例：明天下雨吗 -> unknown

用户侧只送用户的原话。模型在这一档不写任何面向用户的文字，它的全部作用是从固定的标签里挑一个。

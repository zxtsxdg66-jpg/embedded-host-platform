# Android 第一阶段：PC ↔ Android 链路测试流程

> **本阶段唯一目标**：让 Android 真正从 PC 拿到数据，并通过 WebSocket 实时收到数据。
> 不做最终 UI、不做图表、不做历史数据。
>
> **数据来源声明**：真实 STM32 尚未接入前，本流程用 PC 端的**软件模拟数据源**验证链路。
> 界面上会明确显示"PC 处于 simulator 模式，数据为软件模拟，不是真实 STM32 采集值"，
> 请不要把这一阶段跑通等同于"真实硬件数据已打通"。

---

## 零、准备：确认环境

| 项目 | 要求 |
| --- | --- |
| PC 与手机 | 连到**同一个** Wi-Fi 或手机热点（这是能互通的前提） |
| PC 端依赖 | 已安装 `fastapi` / `uvicorn` / `websockets`（本次任务已安装） |
| Android 工程 | `android/`，用 Android Studio 打开，或用命令行 Gradle 构建 |

---

## 一、PC 启动 API 服务

### 方式一：双击 `run_api_server_手机网关.bat`（推荐）

会依次问你运行模式（模拟 / 硬件），硬件模式还会让你选串口，然后**直接把手机上要填的
地址打在屏幕上**：

```
========================================================
  在手机 App 里填写：

      IP   :  192.168.2.153
      端口 :  8000

  （来自网卡：WLAN）
========================================================

先用手机浏览器打开下面的地址验证连通性，能看到一段 JSON 就说明通了：
    http://192.168.2.153:8000/health
```

这样就不用手动跑 `ipconfig` 再从一堆网卡里挑了——**这一步挑错网卡是最常见的坑**：
本项目开发机上有 9 个 IPv4 地址（Mihomo 代理隧道、WSL、VirtualBox、蓝牙、TAP 等），
其中只有一个是手机能连上的。启动器会自动过滤掉虚拟网卡并按可能性排序，若首选地址
连不上，它还会列出备选地址。

### 方式二：命令行

```bash
python scripts/run_api_server.py
```

默认监听 `0.0.0.0:8000`（`0.0.0.0` 表示接受局域网内其它设备的连接；若写成 `127.0.0.1`
则**只有本机能连**，手机会连不上）。

启动成功会打印：

```
[gateway] mode=simulator
[gateway] NOTE: data is software-simulated, NOT from a real STM32.
[gateway] listening on http://0.0.0.0:8000
[gateway] websocket at   ws://0.0.0.0:8000/ws
```

**成功标准**：出现 `Application startup complete.`，且没有报错退出。

> 接真实 STM32 之后，改用：
> `python scripts/run_api_server.py --mode hardware --port-serial COM3`
> （注意 `--port` 是 HTTP 端口，`--port-serial` 才是串口号，两者不要搞混。）

## 二、在 PC 上先自测 API 是否正常

先在 PC 本机验证，能把"服务端问题"和"手机连不上"这两类问题分开：

浏览器直接打开 <http://127.0.0.1:8000/health>，应看到：

```json
{"status":"ok","mode":"simulator","websocket_subscribers":0,"published_count":123,"dropped_count":0}
```

再打开 <http://127.0.0.1:8000/devices>，应看到三个模拟设备：

```json
{"devices":["sim-env-1-temp","sim-env-1-humi","sim-env-1-noise"]}
```

**成功标准**：两个地址都能返回 JSON，且 `published_count` 会随着刷新不断变大
（说明模拟数据源在持续产生数据）。

> FastAPI 还自动提供了交互式接口文档：<http://127.0.0.1:8000/docs>
> 可以在网页上直接点按钮调用每个接口，排查时很方便。

## 三、查看 PC 的局域网 IP

> **用 `run_api_server_手机网关.bat` 启动的话，这一步可以跳过**——启动器已经把地址打在屏幕上了。
> 下面是手动查询的方法，供备用或核对。

Windows 下打开命令提示符，执行：

```
ipconfig
```

找到你当前联网的那块网卡（通常是"无线局域网适配器 WLAN"）下面的 **IPv4 地址**，
形如 `192.168.x.x` 或 `10.x.x.x`。

**注意**：`ipconfig` 可能列出多个网卡（虚拟机、WSL、VPN 等都会各占一个）。要选的是
**手机所连 Wi-Fi 对应的那一块**。如果不确定，可以逐个试。

**成功标准**：记下形如 `192.168.1.10` 的 IPv4 地址。

## 四、在手机浏览器上先验证连通性（强烈建议先做这一步）

在装 App 之前，先用**手机自带浏览器**打开：

```
http://<刚才记下的PC_IP>:8000/health
```

- **能看到 JSON** → PC 与手机之间网络是通的，可以进入下一步
- **打不开** → 问题出在网络层，与 App 无关，先按下面排查：
  1. 手机和 PC 是否真的在同一个 Wi-Fi（手机连的是 5G 频段、PC 连的是访客网络，都可能互相隔离）
  2. **Windows 防火墙**是否拦了 Python：第一次启动服务时 Windows 通常会弹窗询问，
     如果当时点了"取消"，需要到"Windows 防火墙 → 允许应用通过防火墙"里手动放行 Python
  3. 部分路由器开启了"AP 隔离/客户端隔离"，会禁止同一 Wi-Fi 下设备互访，需要在路由器里关闭
  4. 服务启动时 `--host` 是否写成了 `127.0.0.1`（那样只有本机能连）

**成功标准**：手机浏览器能看到 `{"status":"ok",...}`。

## 五、构建并安装 Android App

### 方式 A：Android Studio（推荐）

1. Android Studio 打开 `android/` 目录
2. 等待 Gradle Sync 完成（首次会自动下载依赖）
3. 手机开启"USB 调试"并连上电脑，点 Run

### 方式 B：命令行

```
cd android
gradle assembleDebug
```

产物在 `android/app/build/outputs/apk/debug/app-debug.apk`，传到手机上安装即可。

> **已知路径限制（实测）**：本工程位于含中文的路径 `D:\毕业设计\android`。
> - 打包 APK（`assembleDebug`）：中文路径下**可以正常成功**（已通过 `gradle.properties`
>   里的 `android.overridePathCheck=true` 开关处理）
> - 跑 JVM 单元测试（`testDebugUnitTest`）：中文路径下**会失败**（`ClassNotFoundException`），
>   需要把工程复制到纯英文路径再跑，详见 `android/gradle.properties` 里的注释

## 六、在 App 里配置 PC 地址并连接

打开 App，界面顶部：

1. **PC 局域网 IP**：填第三步记下的 IP（不要填 `localhost` 或 `127.0.0.1`——
   那两个在手机上指向手机自己，永远连不到 PC）
2. **端口**：`8000`
3. 点 **连接**

地址会被保存下来，下次打开 App 不用重填。

> 如果用的是 **Android 模拟器**而不是真机，PC 地址填 `10.0.2.2`（模拟器访问宿主机的
> 专用地址），这也是 App 的默认值。

## 七、验证完整链路

点击"连接"后，按顺序应该看到：

| 界面元素 | 预期 |
| --- | --- |
| 连接状态 | `● 已连接` |
| 模拟数据提示 | 显示"PC 处于 simulator 模式，数据为软件模拟…"（simulator 模式下才显示） |
| 设备 | 列出三台设备及其状态，如 `• sim-env-1-temp  在线 / 空闲` |
| WebSocket 状态 | `WebSocket: Connected` |
| 温度 / 湿度 / 噪声 | 三个数值持续刷新（模拟数据每秒更新一次） |
| 最近更新 | 时间戳持续变化 |

**第一阶段最终成功标准**：

- [ ] 设备列表能拉到
- [ ] 设备状态能拉到
- [ ] WebSocket 显示 Connected
- [ ] 温度、湿度、噪声三个数值都在持续变化（不是一直停在 `--`）
- [ ] "最近更新"时间在走

## 八、异常情况验证（建议一并测一下，验证健壮性）

这些是 App 已经处理的情况，值得实际验证一次：

| 操作 | 预期表现 |
| --- | --- |
| 连接成功后，把 PC 上的服务 Ctrl+C 停掉 | WebSocket 状态变为 Disconnected，并显示"N 秒后重连"，不崩溃 |
| 再把 PC 服务重新启动 | App 自动重连成功，数值继续刷新（不需要手动点连接） |
| 故意把 IP 填错再连接 | 显示连接失败原因，不崩溃 |
| 连接过程中把手机 Wi-Fi 关掉再开 | 断开后自动重连 |

## 九、当前阶段**没有**实现的功能（不要按这些去测）

| 功能 | 状态 |
| --- | --- |
| 历史数据查询 | **未实现**。PC 端目前的历史记录只存在于 PyQt6 界面的表格控件内部，`service`/`api` 层没有对应能力，Android 作为独立进程拿不到。需要先扩展 PC 端接口，属于后续任务 |
| 最终毕设 UI / 图表 / 动画 | 未做，本阶段是最小可运行界面 |
| 登录 / 用户系统 / 本地数据库 | 未做，也不在规划内 |
| Android 直连 STM32（蓝牙/WiFi） | **架构上明确不做**：Android 只做 PC 的移动客户端 |

## 十、安全边界说明

当前网关**没有任何鉴权**，且允许所有来源跨域（CORS `*`）、使用明文 HTTP/WS。
这是基于"PC 与手机在同一局域网、内网直连、无敏感数据"这一毕设阶段场景的取舍。
**不要把这个服务暴露到公网或不受信任的网络**；若将来有此需要，应先加上鉴权与 HTTPS。

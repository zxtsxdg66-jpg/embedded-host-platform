## 1. 当前 UI 的主要问题

对照 `activity_main.xml`（157 行）、`themes.xml`（4 行）、`strings.xml` 逐条列出，全部是实际存在的问题，不是泛泛而谈：

### 1.1 结构性问题

1. **没有配色体系**。整个工程**不存在 `colors.xml`**，主题只有一行 `Theme.Material3.DayNight.NoActionBar`，于是 App 实际显示的是 Material3 默认紫色，且随系统在浅色/深色之间切换 —— 与 PC 端深色工业仪表盘完全不是一个产品。答辩现场手机若处于浅色模式，投影出来会是"默认模板 App"的观感。
2. **通篇 `LinearLayout` + `ScrollView` + 分隔线**，没有卡片、没有栅格。三条 `<View android:background="#33000000"/>` 硬编码分隔线是典型的调试页写法。
3. **配置项占据首屏最重要的位置**。`inputHost` / `inputPort` / `buttonConnect` 三个控件在最顶部，用户每次打开 App 首先看到的是"IP 输入框"，而不是环境数据。连接配置是低频操作，却占了最高信息层级。
4. **核心数据的视觉权重最低**。温湿噪是三个 20sp 的普通 `TextView`，字号仅比正文大 4sp；而 `MainActivity.renderChannel()` 把"标签、数值、单位"拼成一整行字符串（`"温度：26.4 °C"`），三者字号完全相同 —— 数字没有任何视觉优先权，与第六节要求正好相反。

### 1.2 状态表达问题

5. **连接状态是两条互相独立的原始文本**，且中英文混杂：`textConnectionStatus`（"● 已连接"，其实只代表 `/health` 探测成功）与 `textWebSocketStatus`（**"WebSocket: Disconnected"**，英文，且断线时会拼上原始异常 message）。用户无法从中判断"系统整体到底正不正常"，还会看到 `Failed to connect to /192.168.2.153:8000` 这类给开发者看的字符串。
6. **没有"数据是否在实时更新"的判断依据**。`textLastUpdate` 只在收到数据时被覆写成一个静态时间戳 `"最近更新：14:23:07"`，不会自己走动。若 WebSocket 假死（TCP 未断但服务端停止推送），界面看起来完全正常，用户无从察觉。
7. **报警只进日志，不进界面**。`onAlarmStatus` 只在 `triggered=true` 时 `appendLog` 一行文字，混在 12 行滚动日志里；三张数值显示没有任何超限视觉反馈。`AlarmStatus` 里已经有 `threshold`、`kind`（ABOVE_MAX/BELOW_MIN）、`triggered` 三个现成字段完全没被用到。
8. **`onStatistics` 是空实现**。网关每条数据都在推 `statistics`（含 `current`/`minimum`/`maximum`/`average`/`sample_count`），Android 端全部丢弃 —— 这是**已经在链路里、经过验证、却完全没有展示**的真实数据。
9. **没有加载态 / 空态 / 错误态**。点"连接"后到结果返回之间界面毫无反馈（REST 超时 5 秒，最长可空白 5 秒）；三个数值在没数据时显示 `"温度：--"`；`textDevices` 的初始值是字符串 `"--"`；REST 失败时把 `HTTP 500: ...` 原样贴到设备区域。

### 1.3 表现层问题

10. **monospace 调试日志常驻首页底部**（`textLog`，12 行滚动），内容是 `[14:23:07] PC 可达，mode=simulator` 这类开发者信息，是"测试页面"观感最强的一处。
11. **模拟数据警示条只是一行 12sp 灰字**，比正文还小。而"当前数据是模拟的还是真实 STM32 的"在答辩时是必须一眼可见的信息。
12. **无产品身份**。标题栏被 `NoActionBar` 去掉了，App 内没有任何地方写明这是"地铁站环境监测系统"；启动图标是 Android Studio 默认的绿色机器人。
13. **`renderChannel` 用 `String.format("%.1f")` 统一保留一位小数**：温度 26.4 合理，湿度 58.0% 应显示为 58，噪声 42.3 合理 —— 每个通道的小数位应各自决定。
14. **数字宽度抖动**：默认字体是比例字宽，数值从 9.9 跳到 10.0 时整行会横向跳动，大字号下非常明显。

## 2. 建议保留的部分（不动它）

这些是第一阶段做对的地方，改动它们只会引入风险：

- **`data/` 四个文件的全部逻辑**：REST/WS/解析/模型，一行不改（理由见第 0 节）。
- **`MainActivity` 的连接流程顺序**：`/health` 探测 → `/devices` → 逐台 `/devices/{id}/status` → 建 WebSocket。这个顺序能区分"PC 没开/IP 错"与"WebSocket 有问题"，是有意设计，保留。
- **`ServerConfig` 的持久化机制与 `10.0.2.2` 默认值**（模拟器专用回环地址的注释也保留）。
- **`GatewayWebSocket.Listener` 的七个回调签名**：新 UI 完全基于这七个回调驱动，不新增、不改签名。
- **`mode == "simulator"` 时提示"数据为模拟"这个行为本身**（只升级它的视觉表现）。
- **协程 + `Dispatchers.IO` 的线程模型**，以及"回调已在主线程"的约定。
- **`network_security_config.xml` 与 `usesCleartextTraffic`**：局域网 http/ws 明文通信必需。
- **`minSdk 24` / ViewBinding / Kotlin + XML** 技术选型。

## 4. 页面结构

### 4.1 结论：**2 个页面，不引入 Fragment / Navigation / BottomNavigation**

> **2026-09-17 更新**：页面已增至 **4 个**（首页 / 连接设置 / 环境问答 / 历史读数）。
> 本节结论中真正重要的那条**没有变**：仍然不引入 Fragment / Navigation /
> BottomNavigation，新页面一律用 Activity 跳转，理由与下方第三条完全相同——
> 首页只 `onStop` 不 `onDestroy`，WebSocket 保持存活。变的只是页面数量，
> 而当初写"2 个"是因为当时只需要 2 个，不是因为 2 是上限。

```
MainActivity（环境监测首页）  ──[右上角齿轮]──>  SettingsActivity（连接设置）
                             <──[返回]──────────
```

理由：

- 首页承载"系统状态 + 三项指标 + 实时状态 + 设备状态"已经足够，第九节明确要求不为了像完整 App 而堆页面。
- 「设备状态」信息量很小（3 台设备，每台 2 个布尔值），做成独立页面反而空旷，**作为首页底部一个卡片区块**更合适。
- 不用 Fragment 的关键原因是**风险**：WebSocket 实例由 Activity 持有、`onDestroy` 关闭。引入 Fragment/Navigation 会带来额外的生命周期路径，而本阶段禁止改动网络层来适配 —— 用 Activity 跳转则 `MainActivity` 只会 `onStop` 不会 `onDestroy`，WebSocket 保持存活，行为与现在完全一致。
- ~~「历史数据」页**不做**：PC 端 `service`/`api` 三层无此能力（`tests/gateway/test_server.py` 有一条 404 断言把这个决定钉死），不伪造、不读 PyQt6 的 `_history_list`、不画假曲线。~~
  **2026-09-17 撤销**：历史已成为平台自身的能力（`ApiInterface.query_history`），那条 404 断言
  已按留痕方式替换。当初拒绝的理由一条也没被推翻——现在照样不伪造、不读 `_history_list`、
  不画假曲线，历史页显示的是 PC 真实存下来的读数。变的是前提，不是原则。

### 4.2 一个必须处理的副作用：屏幕旋转

当前 `MainActivity` 旋转会被销毁重建 → `onDestroy` 关掉 WebSocket → 重新走一遍连接流程。这在第一阶段没暴露，因为测试时没转过屏。

处理方式（**不改网络代码**）：在 `AndroidManifest.xml` 给 `MainActivity` 加 `android:screenOrientation="portrait"` 锁定竖屏。监测类客户端锁竖屏是常规做法，同时也让布局只需要设计一套。

## 6. 视觉风格

### 6.1 基调：固定深色工业风，与 PC 端同源

不用 `DayNight`，固定深色（`Theme.Material3.Dark.NoActionBar`）。理由：与 PC 上位机的深色仪表盘（`src/ui/theme.py`）视觉同源，答辩时两端同框展示是一套产品；监测场景长时间盯屏，深色低疲劳；避免浅/深两套配色都要调、都要验的双倍工作量。

### 6.2 配色（新建 `res/values/colors.xml`）

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| `bg_base` | `#0D1520` | 页面底色（深蓝灰，不用纯黑，避免 OLED 上过硬） |
| `bg_card` | `#16212E` | 卡片背景 |
| `stroke_card` | `#243347` | 1dp 卡片描边（用描边而非阴影划分层次，更"工程感"） |
| `text_primary` | `#E8EEF5` | 数值、标题 |
| `text_secondary` | `#8FA3B8` | 标签、单位 |
| `text_tertiary` | `#5A6E85` | 日志、时间戳 |
| `accent` | `#00D9A5` | 主强调（青绿，取自 PC 端主强调色）、在线状态、实时标识 |
| `state_warn` | `#FFB454` | 警告：正在连接/重连中/模拟数据提示 |
| `state_alarm` | `#FF5C5C` | 报警：阈值超限、网络异常 |
| `state_idle` | `#5A6E85` | 离线/无数据 |

**明确不做**：渐变背景、彩色阴影、玻璃拟态、霓虹发光。分层只靠"底色 + 卡片色 + 1dp 描边"三级。

### 6.3 圆角与间距（新建 `res/values/dimens.xml`）

- 圆角统一 `8dp`（卡片）/ `4dp`（Chip、按钮）。不用 16dp+ 的大圆角，避免消费类 App 观感。
- 间距用 4 的倍数：页面边距 16dp，卡片间距 12dp，卡片内边距 16dp。
- 卡片不加 elevation（`app:cardElevation="0dp"`），改用 `app:strokeWidth="1dp"`。

### 6.4 字体

不引入任何自定义字体文件（避免体积与版权问题），只用系统字体的字重区分：

| 元素 | 规格 |
| --- | --- |
| 指标数值 | `44sp`, `sans-serif-medium`, `text_primary`, **`fontFeatureSettings="tnum"`** |
| 数值单位 | `16sp`, `text_secondary`, 与数值基线对齐 |
| 指标名称 | `13sp`, `text_secondary`, `letterSpacing 0.05` |
| 统计小字 | `11sp`, `text_tertiary` |
| 页面标题 | `18sp`, `sans-serif-medium` |
| 日志 | `11sp`, `monospace`, `text_tertiary` |

`tnum`（表格数字）是解决问题 14 的关键：等宽数字让数值跳变时不再横向抖动。

## 7. 数据卡片设计

### 7.1 布局：三张全宽卡片纵向排列

不做两列栅格 —— 手机竖屏宽度下两列会把数值压到 28sp 以下，与"数值优先"冲突。全宽卡片可以让数值做到 44sp 且左右还有空间放统计与状态。

单张卡片（高约 108dp）：

```
┌──────────────────────────────────────────────┐
│ 温度                                 ● 正常   │   ← 13sp 名称 / 状态 Chip
│                                              │
│  26.4 ℃                  最低 24.1  最高 28.9 │   ← 44sp 数值 + 16sp 单位
│                          平均 26.2  样本 316  │   ← 11sp 统计（M11）
└──────────────────────────────────────────────┘
```

### 7.2 数值与单位的视觉关系

- 数值 44sp、单位 16sp，**约 2.75 倍差**，确保单位不抢焦点（第六节要求）。
- 单位与数值底部对齐（`baseline` 对齐），中间 4dp 间隔。
- 名称放在数值**上方**而非同一行，避免"温度：26.4 ℃"这种把三者拉平的写法。

### 7.3 每通道独立的小数位

| 通道 | 显示 | 依据 |
| --- | --- | --- |
| 温度 | 1 位小数（`26.4`） | AHT20 分辨率足够 |
| 湿度 | 整数（`58`） | 湿度传感器精度 ±2%，1 位小数是虚假精度 |
| 噪声 | 1 位小数（`42.3`） | 与 HH_07.06 输出一致 |

### 7.4 状态表达（全部基于已有的 `AlarmStatus` 字段，不新增协议）

| 状态 | 触发条件 | 表现 |
| --- | --- | --- |
| 正常 | `triggered == false` | 青绿点 + "正常"，卡片描边保持默认 |
| 超限 | `triggered == true` | 红点 + "超限"，卡片描边变红（1dp→2dp）、数值转红 |
| 无数据 | 该通道尚未收到任何 data | 灰点 + "等待数据"，数值显示 `--` |

超限时同时把 `threshold` 与 `kind` 翻译成人话显示：`ABOVE_MAX` → "高于上限 35.0 ℃"，`BELOW_MIN` → "低于下限 30 %"。

**注意边界**：PC 端只有温度/湿度/噪声三个通道有阈值规则，其它通道不会推 `alarm_status` —— 三张卡正好全覆盖，不存在"某张卡永远停在无状态"的问题。

### 7.5 统计信息（M11，强烈建议做）

`onStatistics` 现在是空实现，而网关每条数据都在推 `minimum`/`maximum`/`average`/`sample_count`。把它们以 11sp 小字放进卡片右侧：

- 这是**真实的、已验证的后端数据**，不是伪造的历史；
- 让每张卡从"一个孤立数字"变成"有量程感的指标"，答辩时可讲的内容明显更多；
- 零协议改动、零网络代码改动，只是把已经收到却丢掉的东西显示出来。

## 8. 实时数据展示方式与"实时感"

### 8.1 实时状态条（M5，必要）

```
◉ 实时 · 2 秒前更新 · 本次会话已接收 316 条
```

三个元素各自的作用与实现（全部 UI 层，不碰网络代码）：

| 元素 | 实现 | 说明 |
| --- | --- | --- |
| `◉ 实时` | 收到 `onData` 时短促脉冲（240ms alpha 动画） | 不是常驻循环动画，只在真的有数据到达时闪一下，既省电又诚实 |
| `2 秒前更新` | UI 层 1 秒 tick 的 `Handler`，计算 `now - lastDataAt` | **走动的相对时间**是"页面是活的"最有力证据，比静态时间戳强得多 |
| `已接收 316 条` | UI 层计数器，`onData` 自增 | 与 PC 网关 `/health` 的 `published_count` 是同一类证据 |

### 8.2 数据停滞检测（M5 的关键部分）

同一个 1 秒 tick 里判断：`now - lastDataAt > 10s` 且 WebSocket 仍标记为已连接 → 状态降级为 **"● 连接正常，但 10 秒无新数据"**（琥珀色）。

这解决问题 6：WebSocket 假死时界面不再"看起来一切正常"。纯 UI 层派生，`GatewayWebSocket` 一行不改。

### 8.3 数值更新微动画（M14，可选）

数值文本变化时，颜色从 `accent` 在 300ms 内过渡回 `text_primary`（一次性 `ValueAnimator`）。**不做**数字滚动动画、不做卡片缩放、不做常驻呼吸灯 —— 数据 3 秒一轮，动画必须短于更新间隔，否则视觉上永远在动，长时间看会累。

### 8.4 会话内实时曲线（M15，可选，需你拍板）

在指标卡内嵌一条 40dp 高的迷你曲线，数据源是**本次连接以来 App 自己收到的点**（内存中保留最近 60 个点）。

- 这**不是伪造历史**：每个点都是 WebSocket 真实推送过来的，App 只是把自己看到的东西画出来；
- 但必须**明确标注"本次连接以来"**，且断开重连后清空，绝不暗示这是 PC 端存储的历史数据；
- 实现方式：自绘 `View`（`onDraw` + `Path`），约 80 行，**不引入 MPAndroidChart 等第三方图表库** —— 与 PC 端 `ChartWidget` 手绘的做法一致。

**如果你认为这有"看起来像历史数据"的答辩风险，就不做**，指标卡不放曲线，方案其余部分完全不受影响。

## 9. 连接状态展示方式

### 9.1 状态机（UI 层派生，网络层零改动）

当前有两个割裂的状态文本。新方案在 UI 层定义一个 `ConnectionUiState`，由**已有的**回调与 UI 计时器共同驱动：

| 状态 | 显示 | 颜色 | 由什么派生 |
| --- | --- | --- | --- |
| 未连接 | ● 未连接 | 灰 | 初始态 / 用户主动断开 |
| 正在连接 | ● 正在连接… | 琥珀 | 点击连接 → `/health` 返回前 |
| 系统在线 | ● 系统在线 | 青绿 | `onConnected()` 之后，且 10s 内有数据 |
| 数据停滞 | ● 已连接，暂无数据 | 琥珀 | `onConnected()` 后但 `now - lastDataAt > 10s`（8.2） |
| 自动重连中 | ● 自动重连中（3 秒后重试） | 琥珀 | `onDisconnected()` 之后 |
| 网络异常 | ● 网络异常 | 红 | `/health` 失败，或连续重连 ≥3 次仍未成功 |

「自动重连中」与「网络异常」的区分只用 UI 层的一个失败计数器，**不读取也不修改 `GatewayWebSocket` 的 `retryAttempt`**。

### 9.2 关于 `onDisconnected(reason)` 里的重连秒数

`GatewayWebSocket.scheduleReconnect()` 现在会把 `"（3s 后重连）"` 拼进 reason 字符串。严格说这是展示逻辑写在了网络层，但**本阶段不改它**（属于已验证代码）。UI 层的处理：把整个 reason 当作不透明字符串，只放进折叠的运行日志里；顶部状态条显示的是我们自己的中文状态文案，不直接贴 reason。这样既不改网络代码，用户也不会再看到 `Failed to connect to /192.168.2.153:8000`。

### 9.3 断线反馈：明确但不打扰

- **不用**弹窗、不用 Toast 轰炸、不用声音（第五节要求）。
- 顶部状态点变琥珀 + 文案变化，这是唯一的主动提示。
- 三张指标卡的数值**保留最后一次的值**并整体降低到 60% 透明度，加一行 11sp 灰字"数据已停止更新"—— 让用户知道看到的是旧值，但不清空（清空会让人误以为系统崩了）。
- 恢复后：透明度恢复、灰字消失、状态点转青绿、脉冲恢复。全程无需用户操作。

### 15.5 追加：背景图与面板半透明化（2026-08-16 晚，用户追加要求）

对应 PC 端的"GUI 背景视觉层"（`ui/widgets/background_widget.py` + `ui/theme.py` 的 rgba 分档），
在 Android 上做同一件事。

- **层次**：`FrameLayout` 最底放 `ImageView`（`scaleType="centerCrop"`，等价 PC 的 `cover_source_rect()` 不变形铺满）→ 半透明遮罩 `View` → 内容层。背景放在 `ScrollView` **之外**，滚动时固定不动
- **图片**：用户提供 1280×2560 竖图，转为 **1080×2160 WebP（质量 80，236 KB）** 放在 `res/drawable-nodpi/`。放 `drawable-nodpi/` 是刻意的——普通 `drawable/` 会按屏幕密度把位图当 mdpi 资源放大，在 xxhdpi 手机上白白占掉约 9 倍内存。APK 由 6.19 MB 增至 6.54 MB
- **遮罩**：`scrim = #330D1520`（0.20）
- **面板分档**（`colors.xml`，越重要越不透明）：指标卡 `panel_metric` 0.82 > 顶部状态区 `panel_header` 0.78 > 辅助卡 `panel_aux` 0.74
- **次级/三级文字提亮一档**：`text_secondary` `#8FA3B8`→`#A8BACD`、`text_tertiary` `#5A6E85`→`#7C90A8`。半透明面板抬高了文字背后的实际亮度，不提亮的话这两级会掉到约 4.0:1 与 2.5:1

> **第一版参数（scrim 0.40 / 面板 0.90-0.86-0.82）经用户实看后判定"背景太淡"**，遂调整为上述值。
> 调整思路：**主要降遮罩、少降面板透明度**——遮罩决定的是"你真正看得见图的那些区域"（卡片间隙、页面边距、上下留白）有多清晰，而面板透明度只影响"图透过卡片的虚影"，后者恰恰是直接吃读数的部分。因此遮罩从 0.40 砍到 0.20（降幅 50%），面板只从 0.90 降到 0.82（降幅 9%）。
- **新增 `bg_inline_panel`**：实时状态条是全页唯一一处正文直接压在背景图上的地方（其余都在卡片里），单独给它加了与指标卡同级的底，否则 11sp 小字会在深浅交错的画面上时隐时现

**对比度是算过的，不是凭感觉**。按最坏情况（背景取纯白像素）逐层复算 alpha 后：

| 文字 | 所在面板 | 最坏情况对比度 | 判定 |
| --- | --- | --- | --- |
| 指标数值（`text_primary` 44sp） | 指标卡 0.82 | **≈8.9 : 1** | 超过 WCAG AAA（7:1） |
| 指标名/单位（`text_secondary`） | 指标卡 0.82 | **≈5.2 : 1** | 达到 AA（4.5:1） |
| 状态栏副标题（`text_secondary` 11sp） | 顶部 0.78 | **≈4.7 : 1** | 达到 AA |
| 实时状态条（`text_secondary` 11sp） | 内联底 0.82 | **≈5.2 : 1** | 达到 AA |
| 设备 id（`text_primary` 14sp） | 辅助卡 0.74 | **≈7.1 : 1** | 达到 AAA |
| 统计小字/日志（`text_tertiary`） | 指标卡 0.82 / 辅助卡 0.74 | ≈3.2 : 1 / ≈2.5 : 1 | 低于 AA，见下 |

`text_tertiary` 是刻意的低权重信息（统计小字、"本次连接以来"、运行日志、设备占用状态）。它在**加背景之前**、在完全不透明的卡片上就只有约 3.1:1，本身就不是按正文标准设计的；提亮一档后在指标卡上回到 3.2:1、在辅助卡上 2.5:1。若真机上觉得吃力，再提亮 `text_tertiary` 一档即可，不影响其它层级。

**离线合成校验**：由于没有真机可跑，用 `PIL` 把 `activity_main.xml` 的层次（背景 → 遮罩 → 各档 alpha 面板 → 各级文字）按相同 alpha 复算成一张 1080×2160 的合成图，人工核对了构图与可读性，结果见 `docs/10_AndroidClient/预览_首页背景合成效果.png`。**它是按 alpha 复算的近似图，不是真机截图**，字体度量、圆角、`sparkline` 真实形状都与实机有差别，不能替代真机验证。

**调节旋钮**（全部在 `colors.xml`，改完不需要动布局与代码）：

| 想要的效果 | 改哪个 | 当前值 |
| --- | --- | --- |
| 页面空白处的背景更清晰/更淡 | `scrim` 前两位十六进制 | `33` = 0.20 |
| 卡片下的背景虚影更强/更弱 | `panel_metric`/`panel_header`/`panel_aux` 前两位 | `D1`/`C7`/`BD` = 0.82/0.78/0.74 |
| 小字看着吃力 | `text_tertiary` | `#7C90A8` |

优先调 `scrim`：它决定"看得见图的地方"有多清晰，且完全不影响读数。`panel_*` 每降一档都会直接吃对比度余量。

### 15.6 追加：App 图标换为用户提供的插图（2026-08-16 晚）

原先是第一阶段手绘的温度计矢量图标，用户要求换成自己提供的插图（1389×1280）。

**关键几何约束**：Android 自适应图标画布是 108dp，但各厂商遮罩只露出中间约 **72dp（66.7%）**，圆形遮罩下的安全区更小（66dp，61%）。所以**不能把整张图直接缩进 108dp 画布**——那样人物会被切掉外圈三分之一。做法是反过来推：先确定"希望被看见的那一块"（940px 见方，含两人的脸与上半身），再向外扩 1.5 倍得到 1410px 的画布裁剪框；越界部分用整图模糊拉伸垫底（这些像素最终会被遮罩切掉，不会被看到）。

**产出的资源**

| 文件 | 用途 |
| --- | --- |
| `drawable-nodpi/ic_launcher_photo.webp`（432×432） | 自适应图标的 background 层 |
| `drawable/ic_launcher_none.xml` | 全透明的 foreground 层占位 |
| `mipmap-{m,h,x,xx,xxx}hdpi/ic_launcher.webp` + `ic_launcher_round.webp` | 传统位图图标 |
| `mipmap-anydpi-v26/ic_launcher{,_round}.xml` | 改为 background=插图 / foreground=空 / monochrome=温度计 |

三点说明：

1. **插图放 background 层而非 foreground 层**。foreground 是给"留白的 Logo"用的，会被再缩进一圈；满幅插图属于背景层。`<adaptive-icon>` 要求两层都存在，所以 foreground 用一张全透明占位图。
2. **顺带补上了一个既有缺口**：工程此前**只有 `mipmap-anydpi-v26`**，API 24/25（`minSdk` 是 24）的设备实际上取不到图标资源。这次补齐了五档密度的位图，并给 `AndroidManifest` 加了 `android:roundIcon`。
3. **温度计矢量图没有废弃，改作 `monochrome` 层**。Android 13+ 的"主题图标"模式下系统只取形状、自行上色，照片/插图无法用于该模式；正好让第一阶段那枚图标继续发挥作用，也顺带消除了 lint 的 `MonochromeLauncherIcon` 提示。

**体积**：位图先按 PNG 生成（665 KB），再统一转为 WebP（质量 88）压到 **103 KB**。APK 由 6.54 MB 增至 6.67 MB。

**方案对比图**：`docs/10_AndroidClient/预览_App图标方案.png` —— 三种裁剪（A 双人合影 / B 右侧角色 / C 左侧角色）各自在放大观察、以及**真实启动器尺寸（48dp，圆形与圆角方形遮罩、深浅两种桌面）**下的样子。当前采用 A。**在 48dp 下 B/C 这类单人特写比 A 更清楚**——这是照片类图标的固有限制（信息密度太高，缩到指甲盖大小就糊），若觉得 A 太糊，换成 B 或 C 只需改脚本里的一组坐标重新生成。

### 15.7 追加：环境问答页与图标改回温度计（2026-09-08）

#### 问答页

PC 网关新增 `POST /assistant/ask` 之后，客户端补上对应界面。**在现有 App 内扩展，不另做应用**：
同一 module、同一包、同一套依赖（OkHttp + `org.json`），没有新增任何第三方库。

| 文件 | 改动 |
| --- | --- |
| `data/Models.kt` | 新增 `AssistantAnswer(text, source)` 与四个 source 常量 |
| `data/MessageParser.kt` | 多认一种 `type: "assistant"`；`text` 缺失按异常数据处理，`source` 缺失退回"系统" |
| `data/GatewayWebSocket.kt` | `Listener` 增加 `onAssistantAnswer`，**带默认空实现**——首页不关心它，不必因此改动已真机验证过的那条路径 |
| `data/GatewayClient.kt` | 新增 `ask()`（POST，读超时单独放宽到 10 s） |
| `AssistantActivity.kt` + 两个布局 | 新页面：气泡列表 + 输入行 |
| `activity_main.xml` / `MainActivity.kt` | 标题栏加一个问答入口按钮 |

三个设计取舍值得记：

1. **模型答案替换而非追加**。同一个问题的两个版本并排显示，会让人以为系统答了两次。
   页面持有最近一条答案气泡的引用，收到 `type: "assistant"` 时就地改写它。
2. **问答页自己开一条 WebSocket**，不从首页转发。首页的连接流程与线程调度是第一阶段真机验证过的，
   为了跨页面传一条消息去改它不划算；网关的事件扇出本来就支持多订阅者、各有独立队列。
   代价是问答页开着时多一条连接。
3. **来源标签四种分开显示**（系统 / 模型识别 / 模型改写 / 未识别），与 PC 端问答面板一致。
   笼统写"AI"会让人分不清"模型只改了措辞"和"模型判断了问题类别、句子仍是程序写的"，
   而这两者该信多少并不一样。

界面用 `LinearLayout` 逐条加视图而不是 `RecyclerView`：一次会话只有十几条消息，
且补送时要直接改写某条已显示的气泡，持有视图引用比通过适配器定位更直接。

#### App 图标改回温度计

用户要求把启动图标换回第一阶段那枚温度计（**应用内的背景插图不变**，仍是
`drawable-nodpi/app_background.webp`）。

- `mipmap-anydpi-v26/ic_launcher.xml`、`ic_launcher_round.xml`：background 改回纯色底
  `ic_launcher_background.xml`，foreground 改回温度计矢量 `ic_launcher_foreground.xml`，
  monochrome 仍复用同一张；
- `mipmap-*/ic_launcher.webp` 与 `ic_launcher_round.webp` 十张位图重新生成
  （minSdk 24，API 24/25 用的是这套传统位图，只改自适应图标不够）。
  用脚本按 108 单位画布的同一组几何参数绘制，4 倍超采样后缩回目标尺寸抗锯齿，
  圆形版另做圆形遮罩。
- `drawable-nodpi/ic_launcher_photo.webp` 保留未删——插图方案的资源仍在，日后想换回去只需改两行 XML。

# 开发约束规则

本文档定义了本项目后续开发（包括由 Claude Code 辅助完成的开发）必须遵守的规则。所有代码贡献均需符合以下约束，违反约束的改动不应被接受。

## 1. 禁止单文件堆积代码

- 单个文件应只承担一个明确的职责，禁止将多个不相关的功能塞进同一文件
- 当文件长度或职责明显超出合理范围时，应拆分为多个模块/文件
- 新功能开发前，应先确定其在 `Software_Structure.md` 定义的目录结构中的归属位置

## 2. 禁止 UI 和通信逻辑混合

- UI Layer 代码中不得直接调用 Communication Layer 或 Protocol Layer 的接口
- UI 与底层逻辑之间必须经过 Application Layer 中转
- 任何在界面代码中出现的串口/网络/协议解析操作都视为架构违规，需重构

## 3. 修改架构前必须说明原因

- 对 `02_Architecture/` 中已定义的分层结构、模块划分做出调整前，必须先在文档中说明：
  - 修改的动机（遇到了什么具体问题或需求）
  - 影响范围（涉及哪些模块/文件）
  - 替代方案的取舍理由
- 未经说明的架构性改动不应直接实施

## 4. 保持模块化

- 模块之间应通过明确定义的接口交互，避免隐式依赖或直接访问彼此内部状态
- 同一层内的不同模块（如不同通信方式）应相互独立，互不影响
- 新增功能应优先考虑复用现有模块的接口，而非在多处重复实现相似逻辑

## 5. 所有功能需要文档说明

- 新增或修改功能模块时，必须同步更新或新增对应的设计文档
- 文档应说明该功能的职责、接口、数据流向，与本文档体系保持一致的组织方式
- 没有文档说明的功能不视为完成

## 6. 保留测试接口

- 各层（尤其是 Protocol Layer 和 Communication Layer）在设计时应保留可供测试的接口
- 应支持在没有真实硬件的情况下，通过模拟数据/模拟通信介质对 Protocol Layer 及以上逻辑进行验证
- 具体测试方案参见 `05_Test/Test_Plan.md`

## 附则

- 本文档为开发阶段的约束性文档，与项目根目录的 `CLAUDE.md` 保持一致；如有冲突，以 `CLAUDE.md` 为准
- 本文档可随项目推进而更新，但任何更新应说明变更原因

## 1. 运行环境要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows（九个 `.bat` 启动器为 Windows 编写；命令行方式跨平台） |
| Python | >= 3.10 |
| Python 依赖 | `pip install -e ".[dev]"`（运行时依赖 PyQt6、pyserial、fastapi、uvicorn） |
| 硬件（可选） | STM32F407 探索者V3 + ATK-MB016(AHT20) + HH_07.06 噪声传感器；**不接硬件也能完整体验**，见下方 Simulator 模式 |

> 无显示环境（CI/远程）下运行 PyQt6 相关内容需设置 `QT_QPA_PLATFORM=offscreen`。

## 2. 九个一键启动器（Windows 下双击即可）

| 双击 | 跑什么 | 需要硬件？ |
| --- | --- | --- |
| `run_gui_模拟数据界面.bat` | PyQt6 上位机界面，**模拟数据** | 否 |
| `run_gui_hardware_真实硬件界面.bat` | PyQt6 上位机界面，**真实 STM32**（会让你选串口） | 是 |
| `run_api_server_手机网关.bat` | Android 网关（会让你选模式，并打印手机要填的 IP） | 模拟模式否 / 硬件模式是 |
| `run_all_界面加网关.bat` | **界面 + 网关一起跑**，共用一条串口 | 模拟模式否 / 硬件模式是 |
| `collect_data_实验数据采集.bat` | 实验数据采集（交互选实验类型与串口，输出 CSV + 统计表格） | 是 |
| `start_llm_启动本地模型.bat` | 启动并预热本地 AI 模型（环境问答用，可选，见 4.1 节） | 否 |
| `stop_llm_停止本地模型.bat` | 把本地 AI 模型从内存卸下（加 `--server` 连服务一起停） | 否 |
| `cloud_sync_导出并上传.bat` | **把攒下的历史数据导成 CSV 归档并上传**（2026-09-17 新增，见 4.3 节） | 否 |
| `cloud_view_查看云端.bat` | **看一眼云上已有哪些文件**，并打开阿里云控制台（只读，2026-09-17 新增） | 否 |

> ⚠️ **硬件模式下要"电脑界面 + 手机"同时看数据，必须用 `run_all_界面加网关.bat`**。不能同时双击
> `run_gui_hardware_真实硬件界面.bat` 和 `run_api_server_手机网关.bat`——串口是独占资源，第二个进程会打不开端口。

### 命令行等价写法

```bash
python scripts/run_gui.py                                   # 等价于 --mode simulator
python scripts/run_gui.py --mode hardware --port COM3       # Hardware 模式
python scripts/run_gui.py --mode hardware --port COM3 --baudrate 115200
python scripts/run_api_server.py                            # Android 网关
python scripts/run_all.py                                   # 界面 + 网关同进程
```

## 3. 两种运行模式

系统提供两种**从界面上看完全一致**的运行模式，区别只在数据从哪来：

- **Simulator 模式（默认，无需任何硬件）**：内部用三个传感器模拟器（温度/湿度/噪声）经内存回环通道产生数据，走**与真实硬件完全相同**的协议编解码、服务分发与界面链路。适合演示、开发与验证界面功能。
- **Hardware 模式（需真实 STM32）**：串口收字节 → 协议解帧 → 数据分发 → 界面，链路为 `SerialChannel → HardwareDeviceReceiver → HardwareRuntimeRunner → ApplicationRuntime → UI`。

两种模式从数据分发层往上的代码**完全相同、零改动**，这是分层架构的直接体现。详见
[`docs/05_Test/Hardware_Simulation_Mode.md`](../05_Test/Hardware_Simulation_Mode.md)。

### 串口怎么选

`run_gui_hardware_真实硬件界面.bat` 与 `run_api_server_手机网关.bat` 会**自动列出候选串口并标注哪个可能是开发板**——
它按硬件 ID 识别 CH340/CP210/FTDI 等 USB 转串口特征，并主动排除蓝牙虚拟串口（本机在没插板子时
就已有两个蓝牙 COM 口，直接取第一个会选错）。按提示选择即可。

## 4. 主要功能界面说明（PC 上位机）

界面为深色工业监控风格的仪表盘布局，自上而下四层：

> **界面是两页的（2026-09-18 起）**：顶部信息栏上有「实时监控」「历史记录」两个页签，
> 点击切换，也可以按 **Ctrl+1 / Ctrl+2**。做成两页是因为历史记录表原先挤在底部一行的
> 左下角，五列内容只有一个角落可用；现在它独占第二页。**状态横幅不在任何一页里，
> 而在两页共用的位置**——系统当前是正常还是报警，不该因为翻了一页就看不见。
>
> 下表中「区域」一列注明了各区域在哪一页。

| 区域 | 内容 | 所在页 |
| --- | --- | --- |
| 顶部信息栏 | 标题、**页签（实时监控／历史记录）**、当前设备、连接指示灯、运行模式标签、时钟 | 常驻 |
| 关键指标卡 | 温度 / 湿度 / 噪声三张大卡片（当前值 + 单位 + 趋势箭头 + 超限时红框），并排第四张**风扇状态卡**（运行/停止 + 当前原因 + 自动/手动） | 实时监控 |
| 实时曲线 | 多通道滚动折线图（含网格、坐标轴数值、图例） | 实时监控 |
| 数据与统计 | 实时数据表（设备/通道/当前值/单位/状态，按设备+通道原地更新）+ 每通道统计卡片（当前/最小/最大/平均/样本数） | 实时监控 |
| 状态横幅 | 一句话的系统状态：正常 / 警告 / 报警 | 常驻（两页都在） |
| 操作区 | 活动日志、**环境问答**面板、**通风控制**面板（温度/湿度通风阈值 + 自动/常开/常关），以及默认折叠收起的**调试控制**（订阅/暂停接收/获取控制权/释放控制权/发送命令） | 实时监控 |
| 历史记录 | **三条通道各占一列**，各自独立滚动，每列三小列（接收时间/数值/状态）；列标题写明通道、单位与供数的设备 | 历史记录 |

> **关于历史记录表（2026-09-17 起）**：读数现在会存到本地数据库（`data/history.sqlite`），
> **关掉程序再打开，之前的数据还在**。订阅某条通道时，表格会先把这条通道已存的读数补进来，
> 再继续追加新到的。
>
> "清空历史记录"按钮**只清掉屏幕上显示的这些行，不会删除数据库里的数据**——重新订阅该通道，
> 记录又会出现。这是有意为之：删数据是不可逆的，不该藏在一个看起来只是"清屏"的按钮后面。
>
> **翻到历史页不会重新查库**，也不需要——表格一直在后台跟着新数据增长，翻页只是把它显示出来。
> 想看更早的数据，重新订阅那条通道即可。
>
> **三列是各自独立的，不是按时刻对齐的一张表**（2026-09-18）。三条通道不是同时到的
> （一轮约 3.09 秒，轮内三个读数相差几百毫秒），硬要把它们并成"同一行三个值"，
> 一旦某条通道丢了一帧，这一行就会把第 N 轮的温度和第 N+1 轮的湿度排在一起——
> 每个数都是真的，但它属于哪一刻错了，而界面上看不出来。所以宁可让三列各走各的。
>
> **每条通道各自保留最近 500 条**，不是三条通道共用 500 条。共用的话，
> 想回看一条通道就只能看到三分之一那么远。

**读数显示几位小数**：温度与噪声保留两位，**湿度显示整数**。这不是偷懒——
AHT20 的湿度精度是 ±2 %RH，写成"56.27 %"是在声称传感器给不出的精度。
**取整只发生在显示这一步**：存进数据库的、助手引用的、上传到云端的，都还是原始读数。
**手机端用的是同一套口径**（2026-09-18 起，APK 已重打）——同一条读数在手机和电脑上写法一致。

**归档 CSV 长什么样（2026-09-18 改版）**：每小时一个文件 `env_年月日_时.csv`，
用 Excel 直接双击打开即可——

| 时间 | 温度(°C) | 湿度(%RH) | 噪声(dB) | 设备 | 备注 |
|---|---|---|---|---|---|
| 2026-09-18 17:33:37 | 27.45 | 57 | 44.70 | mcu-1 | |
| 2026-09-18 17:33:40 | 27.44 | 57 | | mcu-1 | 噪声未上报 |

- **一行是一个采集时刻**，三条通道并排。以前是一行一个读数，同一时刻的三个值
  分散在三行，看一眼要跨三行。
- **某条通道那一轮没上报，格子就空着，并在备注里点名**，不会拿下一轮的值顶上。
- 读数越限或传感器读坏时，数值格留空、备注写明"读数无效（原值 …）"——
  一个不可信的数字放进数值列，会被照样画进曲线里。
- 小数位与界面、手机端一致：温度噪声两位、湿度整数。**取整只在显示这一步**，
  数据库里存的仍是原始读数。
- 文件是带 BOM 的 UTF-8，中文表头在 Excel 里不会乱码。

**启动器的名字直接写明用途（2026-09-19 起）**：根目录那九个 `.bat` 都改成了
「英文名_中文用途.bat」，例如 `run_gui_模拟数据界面.bat`、`cloud_sync_导出并上传.bat`，
双击前不必再查文档。功能与改名前完全一致。

**问它上传、查看与删除（2026-09-18／19）**：

- 说「把数据传上去」，它会回一句还有几个时段没传，**答案底下出现一个「导出并上传」按钮**，
  点一下才真的开始导出上传，进度在新开的控制台窗口里，活动日志也会留一行。
  都传完时它就直说没有待传的，不给按钮；台账读不到时它会让你自己双击 `cloud_sync_导出并上传.bat`。
  **按钮只在电脑上有，手机上没有**——手机看不到那个控制台窗口，传失败了无从判断。
- 说「云上有什么」或「传上去的文件看一下」，答案底下出现**「查看云端归档」**按钮，
  点一下列出云上文件清单并打开控制台。**它只读**——不上传、也不删除，措辞里写明了这一点。
- 说「把旧数据删了」，它会告诉你**删除不在它能做的事情里**，并说明数据分在哪三处。
  这是有意的：删数据不可逆、又没法从一句话里读出该删哪一段，所以没有交给它，
  也没有做成按钮。要清理请自己处理文件，别让它代劳。

**阈值报警**：温度、湿度、噪声三个通道有阈值规则——温度 >35 ℃、噪声 >80 dB(A) 报警，
湿度是 30~75 %RH 的**双向区间**，过干与过湿都报。越限时活动日志出现红字、数据表对应行标红、
指标卡显示红框；恢复正常后自动清除。噪声阈值依据 GB 37488—2019；温湿度两项为工程取值。

**多端留痕**：手机端的每次提问与下发都会在 PC 的活动日志里记一行，
形如「移动端下发：把风扇打开 → 已把风扇切到手动常开」；手机改动的通风设置也会在
一个采集周期内同步到 PC 的通风控制面板。

**通风控制**：温度、湿度各有一条**可在运行时调整**的通风阈值（默认 30.0 ℃ / 80.0 %RH），任一超过即启动风扇，
全部回落即停止。这组阈值与上面的报警阈值是**两套独立的数值**——报警阈值有 GB 37488—2019 的论证依据，不宜为了演示随手改动；
通风阈值本就是工程取值，允许现场调整。另可切换「常开」/「常关」手动接管。

## 4.1 环境问答（PC 界面右下）

在输入框里用自然语言提问，回车或点「发送」。会答的问题：

| 问法示例 | 答什么 |
| --- | --- |
| 现在温度多少 / 湿度呢 / 噪声多大 | 该通道当前读数，并附上距报警阈值还有多少 |
| （接着上一句）最高呢 / 超标了吗 | 沿用上一句问的通道，3 分钟内有效 |
| 超标了吗（此前没问过任何通道） | 反问「你问的是温度、湿度还是噪声？」，回一个词即可，1 分钟内有效 |
| 噪声超标了吗 | 当前值与报警阈值的比较结论 |
| 温度最高 / 最低 / 平均是多少 | 本次运行以来的统计 |
| 噪声的阈值是多少 | 阈值数值与它的依据 |
| 风扇在转吗 / 为什么在转 | 风扇状态与触发原因 |
| 有几个设备在线 | 设备列表 |
| 你能干什么 / 我可以问你什么问题 | 列出能回答的问题 |

### 也可以直接下指令

| 说法示例 | 做什么 |
| --- | --- |
| 把风扇打开 / 关掉风扇 | 风扇切到手动常开 / 手动常关 |
| 风扇交给自动 / 风扇让系统自己决定 | 交回自动模式，按通风阈值决定开停 |
| 把通风温度阈值调到 28 度 | 改通风阈值（温度或湿度） |

指令**只能改这四项**，改的是通风策略而不是直接驱动硬件——写进去的设置和你在通风控制面板里点一下**完全是同一份**，之后由既有的下发逻辑在下一轮轮询送到采集端。所以问答面板不可能做到面板做不到的事。

两点会被拒绝，这是故意的：**数值超出量程**（"调到 300 度"）、**句子里没有数值或有两个数值**（"调低一点"、"从 30 调到 28"）。拒绝时会说明原因，设置保持不变。

**要调的数值是从你原话里取的，不是模型报的。** 模型只判断这句话是哪一类指令；万一它把 28 听成 38，也改不了系统里的任何数字。

> ⚠️ **已知问题：带商量语气的问法会被当成指令执行。** 「风扇是不是该开了」「要不要把风扇打开」
> 「是不是该把通风阈值调到 20 度」这类句子，目前会**直接执行**，而不是回答你风扇现在的状态。
> 想了解情况请用「风扇在转吗」「通风阈值是多少」这种问法；万一被误执行，说一句「风扇交给自动」
> 或在通风控制面板上改回即可，四项设置都能撤回。

表里是**关键词能直接认出**的问法。换一种说法（"外面冷不冷"、"最闹腾的时候多少"）关键词会落空，
此时如果接了本地 AI，它会先给出上面那张"会答什么"的清单，**两三秒后再用真正的答案替换掉**——
因为落空的问句会交给模型去判断你问的是哪一类。模型判断不出来就保持清单不变，不会再冒出第二条消息。

问了它答不上来的（比如问天气、问路），它会**列出会答什么**，而不是猜一个答案。

### 每条回答上的「系统」/「模型改写」/「模型识别」标签

这个标签值得解释，因为它对应的是本功能最重要的一条保证：

- **「系统」**——整句话由程序模板生成。
- **「模型改写」**——数字仍然是程序从实测数据里取的，**只有句子的说法**由本地 AI 重写得自然一些。
- **「模型识别」**——AI 只做了一件事：判断你问的是哪一类问题。句子和数字全是程序自己的。

**AI 永远看不到传感器读数，也永远不负责任何数字。** 它只拿到一句已经写好的话去润色。而且润色完还要再核对一遍：**回答里出现的每一个数字，都必须能在实测数据里找到，否则这次润色直接作废、退回模板原话**。所以你在屏幕上看到的数值，任何情况下都不可能是 AI 编的。

### 它是可选的

不装 AI 也能用。没装、没启动、响应超时，问答**照常工作**，只是措辞死板一些——所有回答都标「系统」。

要用的话需要在本机装 [Ollama](https://ollama.com) 并拉一个模型：

```bash
ollama pull qwen3.5:4b
```

启动时会自动探测，探不到就打一行提示继续跑。想彻底关掉加 `--no-llm`，想换模型加 `--llm-model 别的模型名`。

**演示前建议先双击根目录的 `start_llm_启动本地模型.bat`**：它会在需要时拉起 Ollama，并发一次真实请求把模型载入内存。
不预热的话，第一个问题要多等约 9 秒（模型从磁盘载入）。窗口显示成功后再启动上位机即可；失败也不影响上位机，只是问答走模板措辞。

**用完双击 `stop_llm_停止本地模型.bat`**：模型载入后不会自己退出，会一直占约 3 GB 内存。默认只卸载模型、服务留着；
加 `--server` 连服务与托盘程序一起停。两者都不删除任何模型文件。

**速度参考**（i5-13500H、32GB 内存、无独立显卡）：模板答案 **22 毫秒**内出现；接了 AI 的话，2~5 秒后同一条回答会被改写版本替换掉。**等待期间界面不会卡**，你可以继续操作。

## 4.2 板载屏幕（STM32 开发板上的 2.8 寸 TFT）

硬件模式下，开发板自带的 2.8 寸触摸屏会同步显示一份本地仪表盘，横屏，自上而下：

| 区域 | 内容 |
| --- | --- |
| 标题栏 | 站点名 + 与上位机的握手状态（已连接 / 未连接） |
| 三行数据行（第一页） | 每行：中文标签 + 2 倍放大的数值 + 单位 + 状态（正常 / 报警 / 无效） |
| 底栏 | 风扇状态（运行 / 停止）、语音播报指示、**「语音自检」按钮** |

- **页签「数据」「问答」**：标题栏右侧，点一下切换。「数据」是三行实时读数，
  「问答」显示最近一条问答的结果（种类、数值、是否越限、阈值、来自本机还是手机）。
  帮助文案、反问和指令不会显示在屏上。
- **「语音自检」按钮**：按一次播一句告警语音，三句轮换（温度 → 湿度 → 噪声）。用于演示语音功能——
  现场噪声很难自然超过 80dB。**自检不会写入告警记录、也不计入告警统计**，它只是让喇叭出声。
- **状态"无效"**：表示本周期该通道没有取到有效读数。噪声通道在语音播报期间及其后 3 秒会显示"无效"，
  这是**故意的**：喇叭正在响，此刻测到的是喇叭自己的声音，不是环境噪声。
- **首次上电需要触摸校准**：屏幕会显示五个校准点，依次点击即可，校准值存入板载 EEPROM，**只需做这一次**。
  校准期间开发板不与上位机通信，属正常现象。
- **屏幕只显示开发板自己知道的状态**，唯一的例外是"正常 / 报警"——阈值只有 PC 端有一份，
  由上位机下发给屏幕显示，所以**屏幕上的报警状态与 PC 界面永远一致**，不会各说各话。

> 屏幕出问题不影响主功能：没插屏、屏坏了或初始化失败时，采集、上报、风扇、语音、PC 界面全部照常工作。

## 4.3 历史数据归档（`cloud_sync_导出并上传.bat`）

从 2026-09-17 起，上位机会把每一条读数存进本地数据库 `data/history.sqlite`，
**关掉程序再打开，之前的数据还在**。这个脚本把攒下的数据导成 CSV 归档文件。

**怎么用**：双击项目根目录的 `cloud_sync_导出并上传.bat`。它会把"还没导出过的整点时段"
一次补齐，每个小时一个文件，放在 `exports/` 目录下，名字形如
`env_20260917_15.csv`（本地时间的年月日与小时）。

**先看看会导出什么**（不写任何文件）：在命令行里跑

```
cloud_sync_导出并上传.bat --dry-run
```

**文件长什么样**：六列，用 Excel 或记事本都能直接打开。

| 列 | 含义 |
| --- | --- |
| `ts_local` | 本地时间，给人看 |
| `ts_utc` | 世界时，给机器对账；与上一列是同一时刻 |
| `device_id` | 哪台设备 |
| `channel` | 哪条通道（temperature / humidity / noise） |
| `value` | 读数 |
| `valid` | 1 为有效，0 为无效。无效读数照样留着，它是判断链路质量的证据 |

**几件值得知道的事**：

- **当前这个小时不会被导出。** 它还在写入，现在导只能拿到半截数据，而导过的
  时段不会再导第二次——那半截就永远补不上了。等这个小时过去再跑。
- **跑两遍不会重复。** 已经导过的时段会被跳过，不会产生第二份文件。
- **那个小时没有数据就跳过**，不会生成一个空文件。
- **导出目录不可写时（比如 U 盘拔了）会报错并停下**，但**不会把那个时段记成
  已导出**；把目录恢复后再跑一次，它会补上。

**关于上传到云端（阿里云 OSS）**：导出完成后，脚本会把还没上传的时段依次传上云，
传成功的才在台账里标记。没传上的**留在队列里**，下次再跑自动重传——不需要等待、
不需要重试设置，重试的时机由你决定。

- **还没配置凭证时**：脚本照常导出，只是跳过上传并说明一句，正常结束。
  配置放在项目根目录 `oss_config.json`（参照 `oss_config.example.json` 填写）。
- **现场没网时**：加 `--no-upload`，只导出到本地，一个字节也不往外发。

```
cloud_sync_导出并上传.bat --no-upload
```

### 想看看云上到底有什么

双击 **`cloud_view_查看云端.bat`**。它做两件事，而且**只读**——不上传、不删除、不改动任何东西：

1. 在窗口里列出云上已有的文件（名字、大小、上传时间、合计）；
2. 打开阿里云控制台的文件列表页。

为什么不只开浏览器：控制台要登录、页面也可能改版，而窗口里那份清单是程序自己
查出来的，不依赖登录状态。所以清单才是"文件真的在云上"的证据，浏览器只是顺带。

只想看清单、不想开浏览器：

```
cloud_view_查看云端.bat --no-browser
```

## 5. 常见操作流程

**看实时数据（模拟模式，最快上手）**
1. 双击 `run_gui_模拟数据界面.bat`
2. 在设备列表中选中一个设备
3. 在控制面板中订阅通道（temperature / humidity / noise）
4. 曲线、指标卡、数据表、统计卡片开始实时刷新

**接真实硬件看数据**
1. 接好线并给开发板上电（接线方案见 [`docs/09_STM32Hardware/`](../09_STM32Hardware/)）
2. 双击 `run_gui_hardware_真实硬件界面.bat`，按提示选择开发板对应的串口
3. 其余操作同上

**手机远程查看**
1. PC 端双击 `run_api_server_手机网关.bat`（只看手机）或 `run_all_界面加网关.bat`（电脑手机同时看）
2. 记下窗口打印的 PC 局域网 IP（**不要填 localhost/127.0.0.1**）
3. 手机与 PC 连同一 Wi-Fi/热点，在 App 的连接设置页填入该 IP，返回首页即自动连接

**下发控制指令**
1. 先在控制面板点击"获取控制权"（系统采用"共享读、独占写"：数据谁都能看，命令同一时刻只允许一个客户端下发）
2. 选择命令类型并发送，结果显示在活动日志中
3. 用完点击"释放控制权"

## 6. 常见问题与故障排查

| 现象 | 排查方向 |
| --- | --- |
| 选不到开发板串口 | 确认已装 USB 转串口驱动；启动器已排除蓝牙口，若列表为空说明系统没识别到板子 |
| 硬件模式下打不开串口 | 多半是另一个进程已占用该串口——两端同时看数据请改用 `run_all_界面加网关.bat` |
| 手机连不上 PC | 依次排查：填的是否是 PC 局域网 IP（非 localhost）、防火墙是否放行 Python、路由器是否开了 AP 隔离、手机是否开了代理。详细步骤见 [`docs/10_AndroidClient/第一阶段测试流程.md`](../10_AndroidClient/第一阶段测试流程.md) |
| 手机显示"已连接，暂无数据" | 连接正常但 10 秒未收到新数据，检查 PC 端是否真的在采集（硬件模式下看板子 LED 是否按采集周期翻转） |
| 界面无数据 | 确认已在控制面板订阅通道；模拟模式下若仍无数据请提 issue |
| 开发板断电重启后不运行 | 已知问题（非阻塞）：需接一次 ST-Link。见 `docs/05_Test/Project_Status_Context.md` 5.5 节 |
| 板载屏幕不亮 | 接 USART2 调试串口看是否打印 `LCD ID:xxxx`：有 ID 说明屏检出了、问题在绘制；打印 `[lcd] not detected` 说明没检出，检查排线是否插紧插正 |
| 板载屏幕触摸位置偏移 | 触摸校准值可能没写进 EEPROM。可清空 24C02 中偏移 40 起的 13 个字节后重新上电，会重新进入五点校准 |
| 屏幕上有字显示成空白 | 该字不在内嵌字库子集里。改了屏幕文案后需重新运行 `python scripts/hz_font_to_c.py` 并重新编译烧录 |
| 按了「语音自检」没声音 | 语音数据是否已生成——`alert_pcm.c` 默认是静音占位，需先用 `python scripts/wav_to_c.py 温度.wav 湿度.wav 噪声.wav` 生成再重新编译 |
| 换个说法问就只给"会答什么"的清单 | 关键词没匹配上。等两三秒看是否被真实答案替换；一直不换说明 AI 未接入，或模型判断不出问的是哪一类——换成表里的问法即可 |
| 问答回答全都标「系统」，没有「模型改写」 | AI 未接入。确认 Ollama 已启动（浏览器打开 `http://127.0.0.1:11434` 应有响应）、模型已拉取、启动时没加 `--no-llm`。注意这**不影响回答的正确性**，只是措辞 |
| 问答说"还没有有效读数" | 该通道确实还没收到数据。先在调试控制里订阅通道，或确认硬件模式下传感器正常上报 |
| 项目目录里多了一个 `logs/` 文件夹 | 这是问答日志（2026-09-17 起）：你问过的每句话与系统的回答，一天一个文件，存在 `logs/assistant/`。用途是日后从真实提问里挑出答错的句子补进题库——题库里的句子都是写出来的，不是真人说的。**只写在本机**，不上传、不推送到手机、不显示在板载屏上。可以随时删，删了不影响任何功能 |

# 硬件与固件

## 组成

| 部件 | 型号 | 接口 |
| --- | --- | --- |
| 主控 | STM32F407ZGT6（正点原子探索者 V3 开发板） | — |
| 温湿度 | AHT20（ATK-MB016 模块） | I2C（软件模拟），地址 0x38 |
| 噪声 | HH_07.06 噪声检测模块 | UART TTL 3.3 V，Modbus RTU |
| 通风风扇 | ATK-MB023（驱动芯片 SS6285L） | PWM |
| 显示 | 2.8 寸 320×240 TFT + 电阻触摸 | 板载 TFTLCD 接口（FSMC） |
| 语音 | 板载 ES8388 音频编解码器 + 扬声器 | I2S |
| 与 PC 的链路 | 板载 USB 转串口（CH340C） | USART1，115200 8N1 |

## 引脚分配

| 用途 | 外设 | 引脚 |
| --- | --- | --- |
| PC 链路 | USART1 | PA9 / PA10（经板载 CH340C 转 USB） |
| 调试日志 | USART2 | PA2 / PA3 |
| 噪声传感器 | USART3 | PB10 / PB11 |
| AHT20 | 软件 I2C | SDA = PE0，SCL = PE1 |
| 风扇 | TIM9_CH1 PWM | FI = PE5，BI = PE6（恒低） |
| LCD | FSMC | 数据 PD0/1/8/9/10/14/15、PE7~PE15；控制 PD4、PD5、PF12、PG12、PB15 |
| 触摸 | 软件 SPI | PB0、PB1、PB2、PF11、PC13 |
| 音频 | I2C + I2S2 | PB8/PB9、PB12/PB13、PC2、PC6 |

几处选择的理由：

- **温湿度用软件 I2C 而不是硬件 I2C。** 板载的硬件 I2C1（PB8/PB9）已经挂着 EEPROM 与音频编解码器，
  厂商手册也不建议再接别的器件；传感器厂商的参考驱动本身就是软件 I2C
- **PE0/PE1 与 LCD 共存。** 这两个脚的 FSMC 功能是字节选通，只在按字节访问外部 SRAM 时用到；
  LCD 驱动逐个列出要配成 FSMC 的引脚，不包含它们。接屏之后实测 AHT20 读数正常
- **风扇不照抄厂商例程。** 例程用 TIM1 的一对互补输出，在这块板上那两个脚分别被摄像头接口和音频占着。
  改用 PE5 的 TIM9_CH1：20 kHz PWM、60% 占空比、150 ms 启动脉冲。最初是两个普通 GPIO 全速开关，
  实机上转速过快、有过热保护的风险，才改为调速
- **驱动芯片的 FI 与 BI 绝不能同时为高**（直通状态）。驱动通过"BI 恒低、只切换 FI"从结构上排除这种情况

## 固件结构

Keil MDK + STM32 HAL + ARM Compiler 5.06。仓库只收录自研部分：

```
firmware/stm32f407/
├── User/main.c                 采集周期状态机与命令分发
└── Drivers/BSP/
    ├── PROTOCOL/               帧编解码、CRC-32（与上位机 protocol/ 同一规范，各自实现）
    ├── PC_LINK/                USART1：中断只搬字节，主循环拼帧、校验、重同步
    ├── NOISE_USART/            USART3：寄存器级 RXNE + IDLE 中断，以总线空闲判定一帧结束
    ├── NOISE_SENSOR/           Modbus 请求组帧、应答解析、超时、分贝换算
    ├── MODBUS/                 Modbus CRC16
    ├── SOFT_I2C/  AHT20/       软件 I2C 与温湿度驱动（在厂商驱动基础上加了 CRC8 校验）
    ├── FAN/                    PWM 风扇
    ├── AUDIO_ALERT/            三句预录语音（内部 Flash 中的 PCM），经 I2S 播放
    ├── UI_SCREEN/              LCD 两页界面、触摸、内嵌中文字库
    ├── BOARD/                  三路 UART 的 MSP 初始化集中在一处（HAL 要求全工程只有一份）
    └── DEBUG_LOG/              USART2 调试输出；同时断开 printf 的半主机依赖
```

**不用 RTOS。** 固件要做的是：每 3 秒读两个数字传感器、维护一条与 PC 的串口、按协议收发帧。
这是"主循环 + 中断 + 简单状态机"就能胜任的规模，没有需要抢占式调度的地方。

### 一个采集周期

```
每 3 秒：
  发 Modbus 请求给噪声传感器 ──► 异步等待应答（不阻塞 PC 链路的收发）
  应答落定（或 500 ms 超时）  ──► 读 AHT20（约 80~100 ms）
  三个通道分别组帧上报 PC      ──► 读取失败的通道本轮不上报
主循环每一拍：
  处理 PC 下发的命令并回应答（风扇、语音、LCD 报警位图、问答页）
  只重绘屏幕上变化的字段
```

### 固件与上位机的分工

**固件只采集、执行与显示，不做判断。** 统计、阈值报警、通风决策都在上位机。

| 职责 | 在哪 | 理由 |
| --- | --- | --- |
| 读传感器 | 固件 | 只有它接得到 |
| 组帧、CRC | 两端各自实现 | 只共享协议规范，不共享代码 |
| 统计、阈值判定 | 上位机 | 阈值只有一份，见 [`protocol.md`](protocol.md#为什么报警位图由上位机下发) |
| 风扇开关 | 上位机决策、固件执行 | 固件照命令执行并回应答 |
| 屏幕上的"正常/报警" | 上位机下发位图、固件显示 | 同上 |

屏幕上显示的每一项都是固件确实知道的状态：数值是本机采集的，报警状态是上位机下发的，
风扇与播报是本机执行的结果，"无效"是本周期该通道读取失败。没有一项是屏幕自己推断的。

## 几个工程细节

**播放语音时跳过噪声测量。** 喇叭的声音会把噪声读数顶上去，而那个读数又可能触发新的告警播报——
一个声学反馈回路。所以播放期间整个跳过 Modbus 请求，而不是照常请求再把结果丢掉：
Modbus 应答成功率以发出的请求数为分母，跳过的周期不进分母，指标才干净。

**屏幕上的"语音自检"不经过 PC。** 现场噪声很难自然超过 80 dB，演示需要一个能确定地让喇叭响的入口。
它不上报 PC：自检不是告警，不该进告警记录，也不该消耗上位机的播报冷却窗口。

**中文字库只编进用到的字。** 完整 GBK 字库 250 KB 以上，只能外挂 SPI Flash，而那条 SPI 会占用 JTAG 引脚，
得关掉调试口。屏幕文案只有 59 个汉字，`scripts/hz_font_to_c.py` 扫描界面代码里的字符串字面量，
渲染成 24×24 点阵，共 4484 字节编进内部 Flash。改了文案重跑一次脚本即可。

**断开 printf 的半主机依赖。** 厂商 LCD 驱动里有一句 `printf`。没有重定向时，ARM 的 C 库用半主机实现它，
要靠调试器接管——脱机上电时那条指令无人应答，程序当场停住。现在 `printf` 重定向到 USART2 调试口。

**Keil 会覆盖工程文件。** Keil 开着时修改 `.uvprojx` 会被它内存里的工程模型覆盖回去。
`scripts/check_keil_project.py` 把"工程该长什么样"写成断言：该有的 HAL 源文件、不该列入的文件（如被别的文件 include 进来的 `lcd_ex.c`）、必需的编译选项。缺了这些，表现都是离根因很远的链接或编译错误——比如缺 `--no_multibyte_chars` 时，armcc 按 GBK 解析 UTF-8 中文字符串，报的是"缺少结束引号"。

## 资源占用

加入风扇与语音驱动之后、加入 LCD 与语音数据之前的一次编译：ROM 25,220 字节（1 MB 的 2.4%），RAM 6,760 字节（128 KB 的 5.2%），
其中 4096 字节是音频的 I2S 双缓冲。三句语音各约 3 秒、16 kHz/16 bit 单声道，
合计约 288 KB，放在内部 Flash。

## 已知的硬件侧局限

- **"已连接"指的是已与上位机握手，不是此刻链路通畅。** 上位机只在状态变化时下发命令，长时间没有下行帧是正常的，
  用超时判断会误报。要做成实时指示需要周期心跳，代价是每个周期多一次往返，会挤占留给 Modbus 应答的等待时间
- 电机启动电流较大，建议用板载 DC 适配器供电，不要只靠 USB 取电

## 编译

1. 自备正点原子探索者 V3 的官方 HAL 工程模板（本仓库不含 HAL、CMSIS、启动文件与厂商 LCD/触摸/音频驱动）
2. 把 `firmware/stm32f407/` 下的文件放进模板对应目录，加入 Keil 工程
3. 修改工程文件前先关闭 Keil；改完运行 `python scripts/check_keil_project.py`
